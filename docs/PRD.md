- **시작 화면**: 연습 모드 / 기록 도전 선택. 좌상단 토글로 화면 내 즉시 전환.
- **기록 도전(타임어택)**: 이름 입력 → 자동 립모션 모드 전환 → **부위 2곳 연속 수술**(①표시 부위 절개 → ②드러난 종양 제거 → ③봉합). 첫 정조준 절개부터 타이머. **빗나가면 시간 페널티**(조직 손상). 최종 기록 = 시간+페널티, **우상단 TOP5**(이름 포함, localStorage).
- **절개 시 내부 노출**: 외벽 안쪽 내부 조직층(DoubleSide) — 절개가 깊어지면 붉은 속살이 오목하게 드러나고, 봉합하면 켈로이드(살짝 볼록+옅은 색) 흉터만 남음. X자 바늘땀 제거.
- **수술 장면 연출**: 수술대 + 수술포(타원 개창).
- **무인 어트랙트**: 립모션 모드 30초 무손 → 자동 시연+모드선택 복귀.
- **모드별 UI**: 립모션=로봇 손 / 마우스·시연=레이저 스타일러스. 초록 조준 → 핀치(≥0.85) 발사.

### 콘셉트(구현됨)
- **양손 레이저 원격수술**: 오른손 집게(핀치) → **빨강 레이저 절개**, 왼손 집게 → **파랑 레이저 봉합**.
- **조준 방식**: 손 위치 → 화면 좌표(카메라 레이캐스트, 2.5D). 평소 **초록 레이저로 조준 미리보기**, 확실히 핀치하면(≥0.85) 도구색으로 발사. 검지 끝에서 대각선(왼쪽 위)으로 빔.
- **실제 변형**: 절개하면 장기 메시가 **실제로 갈라지고(파임+검붉게)**, 봉합하면 **아물어 올라오며 X자 바늘땀**이 생김(그림이 아니라 지오메트리 변형).

### 기술 스택(구현됨)
- **웹 / Vite + Three.js**(three ^0.169, npm). 후처리 없음(직접 렌더).
- **사실적 3D 장기 모델**: `public/models/` 에 GLB 배치 시 자동 로드(자동 정규화·배치). 없으면 절차적 위장으로 폴백.
- **입력 모드 3종**: 립모션 / 마우스(폴백) / 자동 시연. **마운트 모드**: 데스크톱 / 헤드마운트.

### 립모션 연동(확정 방법)
- 하드웨어: **오리지널(1세대) 립모션 컨트롤러**.
- 소프트웨어: **Leap Motion Orion 4.1.0**(레거시). 제어판에서 **"웹앱 허용(Allow Web Apps)" 체크 → 웹소켓(ws://127.0.0.1:6437) 활성화**.
  - ⚠️ Gemini V5는 웹소켓 미제공(브리지 필요)이라 채택하지 않음. Orion 4.1이 웹소켓을 기본 내장(설정으로 on).
- 앱은 `ws://127.0.0.1:6437/v6.json`(LeapJS v6 프로토콜)에 직접 연결. 별도 브리지·SDK 빌드 불필요.
- 좌표: 반전 없음(센서 정상 방향). 화면 좌우=손 좌우, 화면 상하=손 앞뒤(palmZ). 핀치=`pinchStrength`.

## 1. 배경 & 문제 정의

수술 절차는 일반인에게 접근성이 낮고, 기존 교육 자료는 영상·텍스트 위주라 "내가 직접 해본다"는 몰입감이 부족하다. 립모션은 별도 장갑·컨트롤러 없이 맨손 동작만으로 3D 인터랙션이 가능해, **부스/전시·오픈캠퍼스·박람회 같은 현장에서 짧고 강렬한 체험**을 만들기에 적합하다.

본 프로젝트는 임상 훈련용 정밀 시뮬레이터가 **아니다**. 목표는 "손동작으로 수술 절차를 따라가 보는 재미있고 직관적인 교육 체험"이다.

### 핵심 성격
- **교육용 체험(experience) 데모** — 임상 정확도보다 몰입감·직관성·완주율 우선.
- **햅틱 없음** — 립모션은 촉각 피드백이 없으므로, 시각·청각 피드백으로 손맛을 대체.
- **짧은 세션** — 1인당 3~5분 내 완주 가능한 분량.

- 맨손 제스처만으로 수술 절차 1건을 처음부터 끝까지 체험.

## 4. 콘셉트 (확정): 립모션으로 조작하는 로봇수술

**집도의가 손을 움직이면 로봇팔이 따라 움직이는 원격조작(teleoperation) 방식** — 실제 다빈치(da Vinci) 로봇수술이 작동하는 원리를 체험으로 옮긴다.

### 왜 이 콘셉트가 립모션과 잘 맞나
- **촉각 부재가 콘셉트상 자연스럽게 가려짐**: 실제 로봇수술도 집도의가 조직을 직접 만지지 않고 콘솔에서 원격조작한다. 립모션의 약점(햅틱 없음)이 오히려 리얼리티가 된다.
- **직관적 매핑**: 손 위치 → 로봇팔 끝(엔드이펙터), 핀치 → 도구 작동(레이저/그래스퍼). 거울 모드와 결합하면 학습 없이 조작 가능.
- **정밀도 요구 완화**: 로봇팔은 스무딩(Lerp)·IK로 손 떨림을 흡수하므로, 립모션의 미세 정밀도 한계를 보정할 수 있다.

### 인터랙션 매핑
| 사용자 동작 | 로봇 반응 |
|---|---|
| 손 이동(x/y/z) | 로봇팔 엔드이펙터가 IK로 추적 |
| 핀치(엄지+검지) | 도구 작동(레이저 절개/봉합, 또는 그래스퍼 집기) |
| 모드 전환 | 절개(우측팔) ↔ 봉합(좌측팔) 등 도구 전환 |

### 수술 절차 (MVP)
- 참고 프로토타입(`docs/수술 시현 프로그램 10.html`) 기준: **레이저 절개 → 레이저 봉합** 2단계.
- 향후 확장: 그래스퍼로 견인, 클립 결찰 등 로봇수술 술기 단계 추가.

### 입력 모드 (부스 운영용 3종)
- **립모션 모드**: 실제 손 조작(메인).
- **마우스 시뮬레이터**: 립모션 없이도 조작 가능(폴백·개발용).
- **자동 시연(어트랙트)**: 무손 시 스스로 시연.

> 참고 프로토타입은 시각·인터랙션 목표(target)로 활용하되, 립모션 연결/듀얼 모드/오프라인 대응은 클린 구조로 재구현한다(§5, §6).

## 5. 기술 스택 추천 (확정 근거: 립모션 1세대 컨트롤러 보유)

### ✅ 확인된 사실: 1세대 컨트롤러는 웹(LeapJS) 연동이 사실상 기본 지원
- 1세대 컨트롤러는 통상 **레거시 Leap Motion 소프트웨어(v3.2.1) 또는 Orion V4** 트래킹 서비스로 구동되며, 이 버전들에서는 **LeapJS가 추가 브리지 없이 `ws://localhost:6437`로 바로 연동**된다(공식 확인).
- 참고로 최신 **Gemini V5+**로 트래킹 서비스를 올릴 경우엔 LeapJS가 직접 붙지 않지만, Ultraleap이 공식 배포하는 [UltraleapTrackingWebSocket](https://github.com/ultraleap/UltraleapTrackingWebSocket) 브리지 서버를 쓰면 이때도 LeapJS 호환 연동이 가능하다. 즉 **어느 트래킹 소프트웨어를 쓰든 웹 경로가 막히지 않는다.**
- 결론: "웹은 리스크가 크다"던 이전 우려는 1세대 컨트롤러 기준으로는 크게 완화된다. **웹(Three.js) 옵션을 1순위로 재검토 가능.**

### 옵션 비교 (갱신)

| 기준 | **Web (Three.js + LeapJS)** | Unity |
|---|---|---|
| 립모션 연동 | ✅ 구버전 서비스면 네이티브, Gemini면 공식 브리지로 지원 | ✅ 공식 플러그인 |
| 무게감("가벼운 도구") | ✅ 설치 없이 브라우저 실행, 배포 링크 하나로 공유 가능 | △ 빌드/설치 필요 |
| 시각 품질("조잡하지 않게") | △ WebGL로 충분히 고품질 가능하나, 라이팅/포스트프로세싱에 공수 필요 | ✅ 기본기가 탄탄해 상대적으로 쉬움 |
| 개발 속도/러닝커브 | 팀이 웹 스택에 익숙하면 빠름 | 유니티 경험 필요 |
| 손 트래킹 데이터 형태 | LeapJS가 스켈레톤 좌표 제공 → Three.js에서 직접 렌더링/매핑 구현 필요 | 립모션 Unity SDK가 손 모델/리깅까지 기본 제공 |

### 제안
- **1세대 컨트롤러 + "가벼운 도구" 선호 + 웹 희망**을 종합하면 **Web(Three.js) 우선 추천**으로 방향을 바꾼다.
- 다만 "조잡하면 안 된다"는 요구가 있으므로, Three.js 채택 시 다음에 투자 필요:
  - PBR 머티리얼 + 톤매핑/포스트프로세싱(예: Three.js `postprocessing` 라이브러리)으로 기본 완성도 확보.
  - 립모션 Unity SDK가 기본 제공하는 손/도구 리깅을 Three.js에서는 직접 만들어야 하므로, 손 모델링·본 매핑에 별도 공수 배정.
- **1일 PoC 우선 진행 권장**: 현재 설치된 트래킹 소프트웨어 버전 확인(레거시/Orion V4 vs Gemini V5) → LeapJS 직접 연동 테스트(레거시/Orion) 또는 UltraleapTrackingWebSocket 브리지 연동 테스트(Gemini) → Three.js 씬에서 손 좌표 렌더링까지 확인.
- PoC에서 트래킹 품질/지연이 체감상 부족하면 Unity로 전환하는 폴백 플랜 유지.

## 6. 핵심 기능 (MVP 범위)

### F1. 손 트래킹 & 제스처 인식
- 립모션에서 양손 스켈레톤 수신, 화면 내 손/도구로 시각화.
- 기본 제스처: 핀치(집기), 그랩(쥐기), 벌림/오므림, 스와이프, 포인팅.
- **좌우 축 매핑은 앱에서 제어**: 실측 결과 Ultraleap Visualizer 기본 뷰에서 손 움직임이 좌우 반전되어 보임(뷰어 표시 관례). 트래킹 데이터 자체는 정상이므로, 앱에서 X축 반전(`x → -x`)으로 원하는 방향에 맞춘다. 목표는 "내 손 = 화면 손"이 같은 방향으로 움직이는 직관적 매핑(온보딩 시간 단축). `hand.type`(좌/우 구분)은 정확히 유지.
- ⚠️ 하드웨어를 물리적으로 회전시켜 방향을 바꾸려 하면 트래킹 인식이 깨진다(립모션은 손이 특정 방향에서 진입할 때 최적화됨). 방향 보정은 반드시 소프트웨어에서 처리.

### F1-b. 듀얼 마운트 모드 지원 (데스크톱 / 헤드마운트)
앱은 두 가지 립모션 설치 방식을 모두 지원한다. 시작 화면 또는 설정에서 모드 선택.

| 모드 | 하드웨어 배치 | 손 진입 방향 | 트래킹 설정 | 좌표 매핑 |
|---|---|---|---|---|
| **데스크톱** | 책상에 평평, LED 위로 | 센서 위쪽에서 | `optimizeHMD: false` (기본) | 위에서 내려다보는 뷰 기준 |
| **헤드마운트(HMD)** | 정면(바깥)을 향해 장착 | 센서 앞쪽에서 | `optimizeHMD: true` | 정면 1인칭 뷰 기준, 좌표계 90° 회전 보정 |

- LeapJS의 `optimizeHMD` 옵션으로 모드별 트래킹 방향을 서비스에 알린다.
- 두 모드는 손 진입 축이 다르므로, 앱 내부에 **모드별 좌표 변환 레이어**를 두어 카메라/뷰와 매핑을 분기한다.
- 수술 뷰 연계 제안: 데스크톱=복강경 탑다운 카메라 뷰, HMD=술자 1인칭 시야 뷰(향후 VR 확장과도 자연스럽게 연결).
- 온보딩 튜토리얼은 선택된 모드에 맞는 손동작 가이드를 표시.
- 트래킹 상실 시 안전 처리(도구 정지 + "손을 센서 위로" 안내).

### F2. 온보딩 튜토리얼
- 30초 이내. "이렇게 손을 움직이세요" 애니메이션 + 따라하기 성공 시 진행.

### F3. 수술 절차 진행 (복강경 담낭절제술 3단계 MVP)
- 단계별 목표 표시 → 올바른 제스처 수행 시 다음 단계 언락.
- 관대한 판정(체험용) — 대략 맞으면 성공 처리, 완주율 우선.

### F4. 피드백 시스템 (햅틱 대체)
- 시각: 조직 반응·하이라이트·성공 이펙트·도구 접촉 표시.
- 청각: 집기/절개/클립/성공 사운드.

### F5. 결과 & 리셋
- 완주 시 요약 화면(소요 시간, 단계 완료). 
- 자동 리셋: 일정 시간 무손 감지 시 대기 화면으로 복귀.

### F6. 운영(어트랙트) 모드
- 미사용 시 데모 루프 영상/문구로 관람객 유도.

## 9. 요구사항 — 비기능

- **성능**: 60 FPS 목표(최소 30). 트래킹 지연 체감 최소화.
- **안정성**: 무인 상태에서 2시간+ 연속 구동, 크래시 시 자동 복구/리셋.
- **안전 문구**: "교육용 체험이며 실제 의료 행위가 아님" 명시.
- **접근성**: 큰 글씨, 색약 고려 피드백, 소음 환경 대비 시각 우선.

| "조잡함" 우려 | 브랜드 이미지 | Unity 기반 고품질 에셋·라이팅, 아트 QA |
